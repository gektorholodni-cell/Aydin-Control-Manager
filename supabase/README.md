# Подключение Structra к Supabase

Без настройки приложение работает в демо-режиме: вход с любым паролем, данные только на телефоне.
С Supabase появляются настоящие аккаунты, компания с кодом приглашения и общие для всей команды
проекты, задачи и фотоотчёты.

## 1. Создать проект (делает владелец, один раз)

1. Зарегистрироваться на https://supabase.com (бесплатный тариф подходит для старта).
2. New project, регион **Central EU (Frankfurt)**, придумать пароль базы и сохранить его у себя.
3. **SQL Editor → New query**, вставить весь файл [`schema.sql`](schema.sql), нажать **Run**.
4. Для быстрых тестов: **Authentication → Sign In / Providers → Email** выключить
   *Confirm email*. Перед запуском у клиентов включить обратно.

## 2. Передать ключи в приложение

В **Project Settings → API Keys** (или **Data API**) взять:

- **Project URL** вида `https://xxxx.supabase.co`
- **Publishable key** (`sb_publishable_...`) или старый **anon public** ключ

Оба значения публичные, их можно хранить в репозитории. Ключи `service_role` и `sb_secret_...`
в приложение и в репозиторий не добавлять никогда.

Вписать их в [`config/supabase.json`](../config/supabase.json):

```json
{
  "SUPABASE_URL": "https://xxxx.supabase.co",
  "SUPABASE_KEY": "sb_publishable_..."
}
```

Сборка iOS в GitHub Actions уже берёт ключи из этого файла. Локально:

```bash
flutter run --dart-define-from-file=config/supabase.json
```

## 3. Как пользуются клиенты

1. Директор фирмы вводит email и пароль на экране входа, приложение предлагает создать аккаунт.
2. На экране «Ваша компания» выбирает «Создать» и получает **код приглашения**.
3. Сотрудники регистрируются так же, выбирают «Присоединиться» и вводят код.
4. Каждая компания видит только свои данные (Row Level Security в `schema.sql`).

## Что уже хранится в облаке

| Раздел | Что сохраняется |
| --- | --- |
| Вход | аккаунты Supabase Auth, сброс пароля по email |
| Компания | название, код приглашения, сотрудники и их роли |
| Проекты | создание проекта |
| Задачи | создание, смена статуса |
| Фотоотчёты | альбомы, фото «до» и «после» (приватное хранилище `photo-reports`) |

Остальные разделы (чаты, финансы, склад и т.д.) пока работают на локальных данных.
